# P0：素材与两端兼容验证

本阶段是固定示例的可运行技术验证。尚不提供 P1 的通用教程协议、作者 API、monorepo 或语义布局编译器。示例内部的位置和时间直接写在 `p0/scene.mjs` 中。

## 运行

需要 Node >=22、pnpm 10、Python 3、Java、FFmpeg（含 ffprobe）、Chrome，以及安装了构建依赖的 TurboWarp scratch-blocks 源码 checkout。

```sh
pnpm install --frozen-lockfile
# 默认使用相邻的 ../scratch-blocks，读取其中的 git 对象和 node_modules。
pnpm p0:bootstrap
pnpm test
pnpm p0
pnpm preview
```

没有相邻 checkout 时，在独立目录准备依赖：

```sh
git clone https://github.com/TurboWarp/scratch-blocks.git /tmp/motion-scratch-blocks
git -C /tmp/motion-scratch-blocks checkout 7c58de666658df1bb447d010132aa3914c10f41e
cd /tmp/motion-scratch-blocks
npm ci --ignore-scripts
# 回到 motion 目录后：
TURBOWARP_BLOCKS=/tmp/motion-scratch-blocks pnpm p0:bootstrap
```

bootstrap 将固定 commit 的 git archive 解到本项目 `.cache/turbowarp`，在该快照上调用上游 build.py，本机 checkout 不会被修改。生成入口的 SHA-256 保存到 build.json，每次验证前检查。上游构建有一条原有的 vertical_extensions.js JSDoc warning。

本轮默认 Chrome 为 macOS 的 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，字体为系统 `Arial Unicode.ttf`。其他系统用 `CHROME_PATH` 和 `MOTION_FONT` 指定路径；字体应覆盖中英文。字体加载到浏览器并显式传给 resvg，不依赖视频后端的系统字体搜索。字体文件不拷贝进仓库，report.json 记录实际哈希；更换字体属于重新准备素材。

`pnpm preview` 默认监听 localhost:4173，可用 `PORT` 修改。生成文件放在忽略跟踪的 artifacts/。失败以非零状态退出；若目录已有旧结果，应以本次命令成功和新 report.json 为准。

## 固定来源与实际入口

- TurboWarp scratch-blocks：`7c58de666658df1bb447d010132aa3914c10f41e`，从相邻仓库的 upstream git 对象提取，未使用 Blockdia 修改后的构建产物。
- TurboWarp scratch-gui：`a2946eeb9a9dca7857d7ab53d766b54288c7a2ff`。检查 `src/components/gui/gui.jsx`、`gui.css`、`src/components/blocks/blocks.css` 与 `src/css/colors.css`，整理顶栏、代码/造型/声音标签、分类、toolbox、工作区及舞台/角色占位。`chrome()` 是从这些区域关系整理的受控简化 SVG 模板，输出 chrome.svg；不是完整 IDE DOM 的自动抓取或像素复刻。
- Blockly 是 Scratch Blocks 的旧 Closure 分支，不套用现代 Blockly 的连接检查 API。
- `Blockly.inject()` 建立临时 SVG workspace；`Blockly.Xml.textToDom()` + `domToWorkspace()` 实例化 XML；`BlockSvg.getSvgRoot()`、`getBBox()`、`getRelativeToSurfaceXY()` 提取真实形状与相对坐标。
- `motion_movesteps` 的 `STEPS` 是输入，不是字段；其 `math_number` shadow 的 `NUM` 才是字段。事件帽为 `event_whenflagclicked`。
- `start.nextConnection.connect(move.previousConnection)` 走 `core/connection.js` 的 `checkConnection_()`；实际执行成功连接和不匹配连接的拒绝检查。
- `core/field_textinput.js` 的 `setValue()` 调用 `callValidator()`，但 validator 返回 null 时仍允许暂态非法文字显示。因此准备阶段必须先检查 validator 返回值，再提交并读回实际值；不能把 setValue 不抛异常视为提交合法。P0 检查 20 的提交和读回；P1 应将这些错误翻译为带步骤位置的诊断。

## 素材与播放

7 份结构素材：事件帽、移动 10、连接栈 10、连接栈 20、加法嵌套输入、重复执行 C 形容器、长中文文本。每份保留内部逻辑 ID、opcode、字段值/边界和连接坐标。XML 中未命名的实例也分配确定 ID。

`prepare.js` 在真实渲染后读取 computed style，把 fill/stroke 移到独立 theme.css，保留路径、变换、透明度和描边宽度。绿旗图标转为内嵌 data URI。ID 加素材前缀。此验证的 SVG 子集不接受 foreignObject、filter、脚本、事件属性和未解析的 url 引用，遇到即失败；尚不是面向任意扩展的 SVG 规范化器。

结构 SVG 单独打开没有完整颜色，需要和 theme.css 配套。manifest.json 内含同一份结构和样式，方便固定示例加载。纯配色可改样式，不需要重建几何；字体或字号变化必须重新准备。

准备结束在 finally 中 dispose workspace，检查 workspace 注册表为空。随后浏览器跳转到全新播放器页面，并断言页面不存在 Blockly。浏览器与视频共用纯函数 evaluate 和 frameSvg：完整栈在连接时原子替换两个节点，拖动层跨越 toolbox 与工作区，静态层分别裁剪。视频在浏览器关闭后执行 resvg 合成和 FFmpeg 流式编码。

## 验证与产物

- p0.mp4：1280×720、30 fps、7 秒、210 帧、H.264/yuv420p、无音轨；按半开区间 `i / fps` 采样。
- browser-*.png / video-*.png：两个拖动关键帧、连接 10、连接 20、代表性素材总览。
- report.json：源构建哈希、字体哈希、运行环境、workspace 销毁与隔离检查、字段和连接验证、双端像素误差、准备/合成/管道背压/编码收尾耗时、内存和 ffprobe 实际帧数。
- 自动比较同一关键帧，允许抗锯齿误差：RGB 平均绝对差 <=3/255，任一通道差 >32 的像素比例 <=2.5%。另需人工查看中文、C 形开口、连接和裁剪，不能仅靠全图误差证明局部正确。
- 单元测试覆盖乱序求值、连接边界的原子切换、连接终点及缺失资源失败。

## P0 决策与后续边界

采用 resvg 2.6.2 作为首个离线 SVG 栅格后端，FFmpeg 负责编码。这一受控子集可以共享结构和主题；先保持完整栈/子树素材，P1 继续抽取公共场景协议。

当前每帧重新创建 resvg 并处理整张 SVG（包括字体），没有静态图层栅格缓存，所以不能把此基线视为优化后的吞吐量。编码与合成并行，exportWallMs 是端到端导出时间，compositionMs 是主线程合成累计时间，pipeAndBackpressureMs 和 encoderFlushMs 不等于编码总 CPU 耗时。P4 应引入缓存合成，再在目标机器测定并发/内存预算。

本轮不实现动态 toolbox、通用 SVG/DOM 提取、按字符输入法、完整交互、主题切换 UI 或通用编译器。

## 2026-09-12 本机实测

完整原始数据保存在 [report.json](p0-baseline/report.json)，人工检查截图见 [最终连接帧](p0-baseline/connected20.png) 和 [代表性素材](p0-baseline/gallery.png)。环境：macOS arm64、Node 24.18.0、Chrome 153.0.8010.36、FFmpeg 8.1.2。

| 指标 | 本轮结果 |
| --- | ---: |
| 素材准备（含浏览器启动，不含上游源码构建） | 1.01 s |
| 视频端到端导出 | 28.78 s |
| SVG 栅格与 PNG 合成累计 | 28.72 s |
| 编码进程 CPU（user + sys，含 PNG 解码） | 1.94 s |
| 编码结束等待 | 44.49 ms |
| Node 进程高水位 RSS | 784.30 MiB |
| FFmpeg 进程高水位 RSS | 338.31 MiB |
| Chrome 进程合计 RSS 的采样最大值 | 999.67 MiB |
| 双端 RGB 平均绝对差最大值 | 0.512 / 255 |
| 差异超过 32 的像素比例最大值 | 0.735% |
| ffprobe 实际输出 | 210 帧，7.000 s，无音轨 |

Chrome 只在准备与关键帧检查阶段存在，视频导出前关闭。Chrome 数据取三个检查点的进程合计，不是真实连续峰值；Node 使用 resourceUsage 的进程高水位，FFmpeg 使用 macOS `/usr/bin/time -l`。这些数值不能直接相加当作同时峰值。FFmpeg 独立 CPU/RSS 测量目前仅在 macOS 启用；其他平台仍可生成视频并记录 Node/Chrome 指标。

这份样例通过人工检查：中文与长文本完整、C 形开口和内部积木无遮挡、连接点一致，工具箱原条目保留，字段 20 提交后鼠标移开。准备和导出是单次本机测量，尚未建立冷/热缓存与并发基线。
