# P2 常规代码编辑

P2 在固定 TurboWarp、1280×720、zh-CN / light 基线上扩展常规编辑。示例见 [structural-editing](../examples/structural-editing/tutorial.ts)，原 basic-editing 教程继续使用同一协议。

## 操作与积木支持矩阵

| 能力                     | 契约与边界                                                                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `split(id, to)`          | 拆出指定积木及它的 next/输入子树，放到命名槽或空连接；原父栈重新准备，原位置不自动补接后继。不能拆 shadow。                                                                                                                                            |
| `delete(id)`             | 默认拖动整个子树到 toolbox 后移除；`via: contextMenu` 右键点击删除，保留后继并按 Blockly 规则补接。`direct.delete` 原地瞬时删除子树。删除 reporter 后恢复原 shadow。                                                                                   |
| 输入连接                 | `ref(id).connection('输入名')` 支持 reporter、布尔输入与 C 形语句槽；`next` 保留原含义。槽类型由实际 Blockly 校验，已有非 shadow 子块时拒绝覆盖。                                                                                                      |
| shadow                   | 输入允许同时声明 shadow 和 block；保存完整 fallback 定义、只绘制实际 block。隐藏 shadow 不可编辑/拆出。                                                                                                                                                |
| `type`                   | 真实文本输入字段（文本、数值、角度等，以 Blockly 字段类型为准）；每个暂态字符串准备实际几何，最终值由 validator 校验。                                                                                                                                 |
| `setField`               | 按实际字段名提交值，包括普通文本、数字、下拉枚举及声明的变量 ID；不展示控件操作。规范化或非法值报错。                                                                                                                                                  |
| `choose`                 | 从真实 `FieldDropdown.getOptions()` 取得文本选项与积木配色；呈现同色带箭头菜单，鼠标点击字段打开菜单，再移动并点击选项提交；非下拉字段及未知选项报错。不是任意编辑器顶栏菜单。                                                                         |
| 模拟输入法               | `type(field, text)` 自动决定输入过程；中文使用 @kensio/pinyinjs 分词、生成拼音与反查候选；只有目标词拼音完整时才把该词置于首位，提交后继续下一词。候选层为不透明 macOS 风格横向圆角条，配色来自当前编辑器主题的独立样式。外部 composition 参数已移除。 |
| `highlight` / `annotate` | 使用实际积木轮廓边界高亮，支持纯文本说明；图层有显式时长、工作区裁剪和上下边界避让。                                                                                                                                                                   |
| toolbox                  | 复用完整连续目录、语义分类切换与条目揭示，不按教程条目裁剪。                                                                                                                                                                                           |

验证样例包含 `control_repeat`、`looks_say`、`operator_add`、`motion_setrotationstyle`、文本与数值 shadow；原有事件帽、移动、等待和多 target 样例继续回归。不维护 opcode 白名单：普通定义是否可准备、连接是否兼容均交给固定 Blockly。

限制：不支持拖出 mutation 目录条目、交互式 mutation 修改、图片选项菜单、颜色选择器动画、任意 UI 菜单、失败连接回弹、已占用槽的自动挤出/替换。观众交互与主题/语言切换已在 [P3](p3.md) 实现。教程未知操作与不支持能力在编译阶段报错。

## 状态与缓存

编译按串并行步骤收集实际结构需求，在动画前准备完整的拆分前后、连接前后和输入中间态。每个可见根使用一份完整栈资源；连接结束时原子移除拖动节点、替换父栈，避免双画。拖动终点采用连接后测得的子块锚点，适应容器重排。

组合资源键包含完整定义（含稳定 ID 与隐藏 shadow）、target、来源版本、语言和准备协议。P2 准备协议为 9，P3 原生主题准备已升级为 10；准备脚本散列同样参与失效。缓存是准备会话内的 manifest 去重，不是跨进程磁盘缓存，也不声称不同 ID 之间共享几何。重复编译相同教程不新增资源。静态栅格缓存仍属于 P4。

## 验证与复现

```sh
pnpm build
pnpm test
pnpm test:integration
P2_VIDEO=1 node --test tests/integration/p2.test.mjs
```

集成测试需要已准备的固定源码、Chrome、字体及 FFmpeg，与 P1c 相同。测试覆盖：

- TypeScript → JSON 后编译完全相等、重复准备缓存命中。
- C 形连接锚点、reporter 输入连接锚点、shadow 恢复与最终逻辑图。
- 拆分/删除边界、独立并行分支、同栈冲突诊断、非法 shadow/字段/连接拒绝。
- 顺序和反序采样相等；每个采样中根 ID 与内部可见积木 ID 均无重复。
- 菜单、模拟输入法、长文本与高亮的浏览器/视频关键帧。双端平均通道误差阈值 3，差异像素比例阈值 2.5%（通道差 >32）。

结果写入 `artifacts/p2/`：编译场景及双端 PNG；设置 `P2_VIDEO=1` 额外生成 30 fps 无音轨 MP4 与导出报告。浏览器及视频在素材 workspace 销毁后渲染，不依赖活动 Blockly。

2026-09-13 首轮 P2 验收（输入自动化调整前）：TypeScript 构建、格式检查与 `git diff --check` 通过；单元/集成共 25 项通过，6 组双端关键帧通过像素差异阈值。代表教程导出为 1280×720、30 fps、228 帧、7.6 秒无音轨 MP4，帧数/时长经 FFprobe 检查。这里验证编辑结构与输出一致性，不作为服务器容量或性能预算。

输入自动化调整：中文和混合文本由编译器规划，数字/英文直接逐字符输入；省略 duration 时按内部输入步骤计算时长，仍可用可选 duration 控制整段节奏。词语、拼音和候选由固定 @kensio/pinyinjs 1.7.13 的 full 词典与反向索引生成，候选使用简体形式及词典排序，不联网。词典仅在编译中文输入时异步加载并复用，播放器不加载词典。输入 `chong` 时只显示该读音的候选；`chong q` 的未完成音节保留已完成前缀候选；到 `chong qing` 才将“重庆”置于首位。菜单和 IME 使用独立呈现类型，光标位于候选层与菜单之上。示例在 reporter 连接后增加 0.6 秒停留，避免同一时间边界立即拆分导致看不到拼合结果。

输入自动化调整后复验：21 项单元测试及 5 项真实 Blockly/视觉集成测试通过；7 组双端 PNG 包含菜单移动、选项点击和 reporter 连接后的停留状态。playground 的 `artifacts/p2/scene.json` 已重新生成；旧 MP4 为首轮记录，更新视频可运行 `pnpm p2`。

IME 定位使用准备阶段测得的已提交文本宽度，首个候选文字与当前拼音起点对齐；下划线仅标记预编辑部分。输入文字、光标、候选锚点共用居中和水平滚动计算，起点滚出输入框时使用可见边缘。右侧空间不足时先减少候选数量，无法容纳首选时再平移候选条；垂直方向保留上下避让。新增长文本真实 SVG 字符坐标对照与滚动边界测试。
